# Scoped pstack default recommendations

Keep the existing pstack model rows as fallbacks. When the Jev Model Router plugin is available and its `pstackRouting` opt-in is enabled, use it before spawning agents with these Sol defaults: `feature, refactoring` and `swarm workers` with a worker subagent, and `how explorer` and `why investigators` with a researcher or explorer subagent. This scoped rule takes precedence over those routine defaults. Direct user choices, custom role pins, and panel assignments take precedence over the bridge.

Use the `jev-model-router` plugin skill to locate the installed `recommend-pstack` command. Before an ordinary worker or researcher spawn, construct the original input with `model: "gpt-6-sol"`, `fork_turns: "none"`, and `reasoning_effort: "high"` unless the user supplied another effort. This original Sol/high input is the fallback if the command is disabled, unavailable, or returns `kind: "preserve"`.

Send JSON on stdin with exactly `pstackRole`, `modelSource: "pstack-default"`, `effortSource: "role-default"`, and `spawn`. The `spawn` object is the original proposed input. This marker permits effort selection only when its original effort is high and its agent type is worker or researcher. Explorer model routing retains its original effort. If a user or custom role supplied the effort, use `effortSource: "explicit"` and keep its compatible `reasoning_effort`. The earlier three-key request without `effortSource` still routes models and keeps a present effort fixed; if effort is absent, it remains absent. Do not infer either source from the values alone.

Send the task as JSON without shell interpolation. When the command returns `kind: "route"`, apply its `model` and any returned `reasoning_effort` to the original spawn. Preserve all other fields and do not forward wrapper metadata. `source`, `reason`, and `confidence` describe the model. `reasoning_source`, `reasoning_reason`, and `reasoning_confidence` describe effort independently. The effort choices include `low`, `medium`, `high`, `xhigh` (extra high), and `max`. The router never chooses `ultra` automatically.

For generic unpinned worker and researcher calls, also construct a baseline high input. To ask Jev to select effort, send a copy without that default effort to `recommend` and retain the original high input for the preserve or unavailable path. Explicit user effort stays in the request. The ordinary role's hard-pinned `model_reasoning_effort` profile setting overrides a spawn argument in Codex. Remove only the worker and researcher profile pins if you want dynamic effort, then keep the high baseline in these instructions. Leave expert max, validator high, planner, reviewer, explorer, and panel settings intact. A caller should verify effective effort in a fresh subagent context after changing profiles.

This bridge does not apply to direct user model choices, custom role model pins, expert or validator work, bug and performance slots, strongest-judgment slots, or comparison, race, and panel assignments. A panel-selected Sol still has panel provenance. Do not use Jev as a Codex model slug. `auto` and omitted models retain their inherit-parent behavior. This instruction does not authorize additional subagents.
